# T1000 — ERA Watch Data Analysis

This workspace is the data-analysis component of a DHBW Praxissemesterarbeit
(T1000) at Emerson. It adds a **physical-plausibility data-quality layer** on top
of the existing ERA recording pipeline (Fatemeh Heydari's preprocessing pipeline,
V2.1). That pipeline already performs **statistical** validation and cycle
rejection itself — Stage&nbsp;9 (Validation Rule Generation, robust Median/MAD) and
Stage&nbsp;10 (Dataset Validation, the only rejecting stage). This thesis does **not**
rebuild that. Instead it contributes a complementary **physical floor** that runs
*first*: it checks full mechanical stroke, physically-plausible duration, expected
sample count, per-signal sanity and **in-cycle standstill** against *absolute
physical* values (not the learned population range), then hands the cleaned pool to
the pipeline's statistics. Physics answers *"are these data usable at all?"*;
statistics answers *"is this cycle unusual vs. its neighbours?"* (see
`docs/approach_comparison.md`). It also re-derives the two provisional segmentation
thresholds (session gap `3600 s`, `Position > 1.0`) from data for the pipeline to
apply at the source, and documents the decision logic, data selection, and visual
results that support the thesis.

## Where to look — the three contributions

- **Decision Tree** — the preprocessing decision logic (which cycles/data are
  usable and why):
  - `deliverables/preprocessing_decision_tree.html` — technical version, with all
    thresholds and source references
  - `deliverables/decision_tree_simple.html` — simplified version for
    supervisors
  - Reasoning: `docs/MasterThesis_usefulness_criteria_analysis.md` (EN) /
    `..._de.md` (DE), `docs/pipeline_structure.md`,
    `deliverables/pipeline_stage_overview.html`

- **Data Pool** — the validation/selection code and the generated cycle data:
  - Code: `src/cycle_overlay/` (`extract_cycle_stats.py` →
    `build_dashboard_data.py` → `build_html.py`)
  - Generated data: `src/cycle_overlay/output/` and `outputs/`
    (both git-ignored; regenerated by the scripts)

- **HTML Cycle Visualization** — the browsable dashboard a reviewer opens:
  - `src/cycle_overlay/output/actuator_lifetime_dashboard.html`
    (single self-contained file; a build artifact, git-ignored)
  - Architecture/review: `docs/dashboard_architecture.md`,
    `docs/dashboard_visualization_review.md`

## Top-level layout

- `deliverables/` — browsable HTML results a reviewer opens (decision trees,
  pipeline overview, source guide)
- `docs/` — written documentation and reasoning (criteria analyses, pipeline
  structure, dashboard architecture, file-by-file documentation)
- `src/` — code (`cycle_overlay/`: cycle extraction, dashboard build scripts,
  and its generated `output/`)
- `config/` — configuration and examples (`example_pipeline_stage8.yaml`)
- `notes/` — internal scaffolding (weekly plan, Copilot prompts)
- `outputs/` — generated pipeline output data (git-ignored)
- `session-handoffs/` — working context, not a deliverable (see below)

## Working context (not deliverables)

- `AGENTS.md` — session-context file read at the start of each assistant session.
- `session-handoffs/` — session-continuity log; `LATEST.md` is a symlink to the
  most recent handoff. These are internal working notes, not thesis output.
